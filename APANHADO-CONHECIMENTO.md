# Apanhado de conhecimento — inventário da biblioteca

> Documento de consulta do professor. A versão navegável fica em
> `/professor/biblioteca/apanhado` (menu **Apanhado** no app).
> Atualizado em 2026-11-23 · 41 informações.

## 1. Para que serve

É o índice de respostas rápidas que alimenta a biblioteca de materiais. Em vez de procurar
numa aula longa, o professor busca a dúvida do aluno, vê a resposta pronta e, se quiser,
transforma o cartão em material publicável.

Regra de ouro do cartão, herdada do planejamento de conteúdo:

1. **Português** em cima;
2. **Inglês (ponte)** logo abaixo;
3. **Como se fala** em seguida;
4. **Resposta curta** para o professor usar na aula;
5. **Dicas por L1** como hipótese revisável — nunca como rótulo do aluno.

## 2. Eixos de busca

| Eixo | Valores |
|---|---|
| Nível | A0, A1, A2, B1, B2, C1, C2 |
| Tipo de conhecimento | gramática, léxico, fonética/pronúncia, pragmática/registro, cultura/variação, ensino/estratégias |
| Formato | pergunta comum, regra/explicação, contraste com L1, dica de aula |
| Idioma materno | en, es, fr, de, it, ja, zh, ar |
| Tema | viagem, trabalho, estudo, social, corpo, casa, tecnologia, cultura |

A busca textual ignora acentos e exige todos os termos digitados (AND). Ela varre pergunta,
frase PT, ponte EN, pronúncia aproximada, resposta, tags, palavras-chave e dicas de L1.
Digitar `pronuncia` encontra `pronúncia`; `ser estar` encontra a entrada de ser/estar.

## 5. Como alimentar a biblioteca

1. Abra **Apanhado** e encontre a entrada (busca ou filtros).
2. Clique em **Criar material na biblioteca →**.
3. O formulário de `contents` abre com título, corpo PT/EN/fala, nível, competências e tags.
4. Revise, complete o texto até o mínimo de palavras e publique.

O rascunho de A0 entra como **A1**, porque a coleção `contents` ainda não tem o pré-nível;
o aviso fica registrado no corpo do material.

## 6. Como acrescentar uma informação

Edite [`src/lib/domain/knowledge-bank.ts`](src/lib/domain/knowledge-bank.ts). O tipo
`KnowledgeEntry` está em [`src/lib/domain/knowledge.ts`](src/lib/domain/knowledge.ts);
os campos obrigatórios são `id`, `level`, `type`, `kind`, `question`, `pt`, `en`, `spoken`,
`answer`, `l1Hints`, tags, `skills`, `register` e `keywords`. Depois:

```bash
npm run typecheck
git add . && git commit -m "Adiciona entrada ao apanhado"
```

Não é preciso semear nada no Firestore: o acervo é código versionado, então aparece no app
assim que o Next recarrega e fica revisável no GitHub.
